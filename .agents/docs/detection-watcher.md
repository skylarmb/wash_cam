# Detection watcher

`wash-cam watch` (`wash_cam.watch`) runs on the server and stores a detection for every capture. It migrates the database, loads `VehicleDetector` once, then every `POLL_INTERVAL` (5 s) runs `process_new_images`: each `.jpg` in `tmp/images/` without an `image_detections` row is detected and committed individually. Because it works from "no row yet" rather than file events, it processes any backlog on start and loses nothing across restarts or crashes. Undecodable files are skipped for the life of the process. Rows record per-bay counts, the counted vehicles with boxes and scores, and the model name; see `db/README.md`.

`take_picture()` writes each capture to `<name>.jpg.part` and renames it into place, so the watcher's `*.jpg` scan never reads a half-written file. All modules take the capture directory and database path from `wash_cam.config.IMAGES_DIR` and `DATABASE_PATH`.

On the server, `scripts/install_services.sh` installs launchd agents `com.washcam.capture` (`scripts/capture_loop.sh`, restarted after each run's DURATION), `com.washcam.dashboard`, and `com.washcam.watch`: started at login, restarted on exit, logs in `tmp/logs/`. Re-run it after moving the checkout or changing code the services load. Under launchd the camera permission belongs to the virtualenv's Python interpreter, on the Mac mini a `/nix/store/...python3.13` path approved once on the server's screen; a Python upgrade changes that path and needs approval again. Until then captures fail with `Could not open camera at index 0.` in `tmp/capture.log`. To redo detections after a model or filtering change, delete rows from `image_detections`; the watcher refills them.

Each stored detection also records `brightness`, the capture's mean brightness from 0 to 255 (migration `006`). At startup the watcher measures any rows still missing it and then rebuilds sessions. A capture below `UNUSABLE_BRIGHTNESS` (8) shows nothing usable, and lit nights sit near 30. Sessions and analytics treat such captures as missing, so a run of them is an outage rather than empty bays. Sessions end as `gap`, analytics excludes the time from coverage, and the live strip reports the frame as too dark.
