# Image labels

`db/labels.sqlite3` contains the `image_labels` table. Each row stores the current verified labels for one image. `image_path` is the primary key and holds a path relative to `images/`. `metadata` stores a valid JSON object as text. `verified_at` stores the UTC verification time and defaults to the insertion time. Verification covers the entire image. Updates must set the new verification time explicitly.

The metadata convention uses `vehicles.bays`, an array of entries with stable `bay_id` values and flexible label fields. The dashboard saves `vehicle_count` for wash bays `bay_0` through `bay_4` (leftmost first) and the vacuum station `vac_0`. Zero means an empty bay. An omitted bay has not been labeled. The database requires an object at the JSON root but does not enforce fields or bay IDs. An absent row means no verified labels have been saved.

`db/migrations/001_image_labels.sql` creates the schema and sets `PRAGMA user_version` to `1` in one transaction. The tracked database already contains this migration. Git tracks the database and ignores temporary journal files. Only one developer modifies the database at a time. Pull before labeling, close the connection before committing, and push before the next developer starts. Images stay on disk. The dashboard reads and saves counts through `/api/labels`. A save replaces metadata and updates the verification time. There is no migration runner.
